# Security and privacy gates

The release fails closed unless all P0 gates pass.

- Model packs: immutable revision, path/size/SHA-256, license and runtime metadata; bounded `.part` download; atomic activation and no silent overwrite. Release-channel signed manifests remain a pre-distribution gate. Weights and tokens are never committed.
- Search client: a configured build uses the fixed HTTPS proxy origin and closed request schema. Preview builds fall back to fixed-host, bounded HTTPS GETs to Korean Wikipedia and Open-Meteo only; redirects, arbitrary URLs and oversized responses are rejected. Internet help is recommended during first setup but cannot send until the one-time disclosure is accepted, and remains visibly opt-out. Only the current freshness-sensitive question may leave the device; audio and prior conversation do not. Unsupported volatile categories fail closed in the public fallback. A commercial release still requires app attestation, rate limits, provider-terms review and an evidence-backed retention policy on the production proxy.
- Prompt injection: search is typed untrusted evidence inside explicit delimiters, its embedded instructions are declared non-executable, and summarization has tools disabled. Web output is buffered before display; source provenance is attached independently of model formatting as one representative, validated HTTPS link below the answer. Missing inline citation text never erases or replaces a completed answer. This reduces—not eliminates—semantic prompt-injection risk, so adversarial Korean/English real-model evaluation remains a store-release gate.
- App actions: deterministic Korean routing into an allowlisted typed schema; unknown-field rejection; external intents use `ACTION_DIAL`, visible alarm/map/message preparation, and an explicit confirmation dialog. The LLM does not directly execute tools.
- Voice: microphone only after an explicit press and contextual permission request; raw audio is memory-only; no background capture; playback is stopped and flushed before recording.
- Screen sharing: starts only after an in-app explanation and Android's per-session MediaProjection consent. A foreground notification and in-app banner remain visible, both expose stop controls, and protected app surfaces stay under platform control. Android picture-in-picture provides the optional small microphone window without requesting unrestricted overlay permission. The bounded current frame and OCR aid are memory-only, sent only to the local Gemma 4 runtime, never sent to search, and never written to chat storage. Visible screen text is prompt-injection data, not an instruction. Every stop path (in-app, notification, MediaProjection callback, or service teardown) cancels the active turn and resets the model KV context. Before any ImageBytes/OCR reaches LiteRT, the assistant placeholder boundary must be durably committed; a failed write aborts screen inference. That boundary excludes all screen-derived history from later inference, including partial output after process death, and a missing boundary fails closed.
- Local data: message bodies, their single bounded HTTPS provenance link, and explicitly saved personal memories use Android Keystore AES-256-GCM authenticated encryption before atomic persistence; chat and memory use separate keys. Backups and device transfer are disabled. Users can review and delete saved memories, destructive delete language is exact-match only, and a persisted context boundary prevents older visible chat from repopulating deleted memory into inference. Internet results are never saved as personal memory. The current encrypted-file stores have no DB/WAL/SHM sidecars.
- Android: release cleartext disabled; the launcher is the only component callable by an unprivileged external app (dependency components use signature protection). There is no AccessibilityService, WebView, direct calling/SMS, contact/call-log, arbitrary URI, or broad package-query permission.
- Supply chain now: pinned Gradle distribution hash, documented vendored-AAR provenance/hash, minified release, repository secret scan, TypeScript check and npm audit. Dependency verification metadata, SBOM generation and immutable CI action SHAs remain mandatory before a store release; this repository does not claim those unfinished controls as passing.
- Policy: show that the product is an AI helper that can be wrong, provide message reporting with explicit preview/consent, and align privacy/Data Safety declarations with actual behavior.

AVD currently proves deterministic voice state, Korean STT support probing without a crash, MediaProjection consent/service start/visible stop state, permission denial UI, corrupted-model rejection, one-minute approval expiry, one-time in-process approval consumption, encrypted chat/memory persistence, real E2B KV-cache reuse, a bounded search-injection corpus, representative clickable search provenance, and manifest/network assertions. Process-death approval replay and the full device matrix remain store-release gates. Physical-device QA owns Korean STT availability/accuracy, screen OCR accuracy across OEMs, ARM inference, audio routes, echo, thermal/RAM/battery, and perceived voice quality.
