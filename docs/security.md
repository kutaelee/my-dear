# Security and privacy gates

The release fails closed unless all P0 gates pass.

- Model packs: immutable revision, path/size/SHA-256, license and runtime metadata; bounded `.part` download; atomic activation and no silent overwrite. Release-channel signed manifests remain a pre-distribution gate. Weights and tokens are never committed.
- Search client: fixed HTTPS proxy origin, closed request schema, redirects disabled, timeouts/size caps, and no arbitrary fetch. The included gateway is a non-production scaffold; search remains disabled in ordinary builds until app attestation, per-caller rate limits and an evidence-backed retention policy are deployed.
- Prompt injection: search is typed untrusted evidence inside explicit delimiters, its embedded instructions are declared non-executable, and summarization has tools disabled. Every web answer must contain valid `[자료 N]` references or it is replaced with a fail-closed message. This reduces—not eliminates—semantic prompt-injection risk, so adversarial Korean/English real-model evaluation remains a store-release gate.
- App actions: deterministic Korean routing into an allowlisted typed schema; unknown-field rejection; external intents use `ACTION_DIAL`, visible alarm/map/message preparation, and an explicit confirmation dialog. The LLM does not directly execute tools.
- Voice: microphone only after an explicit press and contextual permission request; raw audio is memory-only; no background capture; playback is stopped and flushed before recording.
- Local data: message bodies use Android Keystore AES-256-GCM authenticated encryption before atomic persistence; backups and device transfer are disabled. The current encrypted-file store has no DB/WAL/SHM sidecars.
- Android: release cleartext disabled; the launcher is the only component callable by an unprivileged external app (dependency components use signature protection). There is no AccessibilityService, WebView, direct calling/SMS, contact/call-log, arbitrary URI, or broad package-query permission.
- Supply chain now: pinned Gradle distribution hash, documented vendored-AAR provenance/hash, minified release, repository secret scan, TypeScript check and npm audit. Dependency verification metadata, SBOM generation and immutable CI action SHAs remain mandatory before a store release; this repository does not claim those unfinished controls as passing.
- Policy: show that the product is an AI helper that can be wrong, provide message reporting with explicit preview/consent, and align privacy/Data Safety declarations with actual behavior.

AVD currently proves deterministic voice state, permission denial UI, corrupted-model rejection, one-minute approval expiry, one-time in-process approval consumption, encrypted persistence, and manifest/network assertions. Real-model search-injection corpus testing, process-death approval replay, 100-turn soak and the full device matrix remain store-release gates. Physical-device QA owns Korean STT availability/accuracy, ARM inference, audio routes, echo, thermal/RAM/battery, and perceived voice quality.
